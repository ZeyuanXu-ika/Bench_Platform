# Bench Platform

支持“多模态证据 → 客观事实 → 复合事件 → 主体情感脉络”的浏览器标注工作台。网页可发布到 GitHub Pages；素材、图谱和结果留在使用者的设备上。无需标注员安装 Python、Docker 或 Potato。

本项目是独立的浏览器应用，包含时间窗、独立事实、事件、情感状态与变化，以及可回溯的有向关系图。各层由人工标注与确认，关联图按已保存的节点和关系自动生成。

## 四层标注流程

1. **证据：** 导入 MP3／MP4 等素材，创建并分类时间窗。需要跨素材联合标注时，展开页面下方的“主体、证据提及与媒体对齐”，设置共同时间轴与偏移；共同时间 = 素材局部时间 + 偏移。独立文件不会自动认定为同步。
2. **主体共指：** 建立统一主体，为视觉人物、说话人或其他提及选择对应证据和主体。别名只记录称呼，身份映射由人工确认；未知主体不会自动合并。
3. **事实：** 点击证据下的“整理为事实”，或进入“事实”页新增。填写第三人称客观描述，选择主体及一个或多个支持证据，核对后设置为“已人工确认”。人物声称某事发生时，使用“人物转述”并记录说话人，避免把发言内容直接当作已经验证的事件。
4. **复合事件：** 选择多条事实，精练成具体事件，填写参与主体并核对共同时间范围。一个事实可以支持多个事件。
5. **情感脉络：** 按主体添加情感状态、共同时间区间、事实依据和关联事件；需要时连接同一主体的前后状态，记录变化及关联事件。每个事件分别选择“关联”或“因果判断”，新增关联默认不作因果断言；多事件可以保留不同的关系，不会因修改说明而全部变成因果。“导致”需要人工判断和依据。稳定情绪可以只有一个状态，不要求编造变化。
6. **关联图谱：** 自动按证据、事实、事件、情感四列生成带箭头与关系标签的 SVG。默认适应宽度，可切换原始尺寸；点击节点聚焦其上下游，证据可回放。每层超过 50 个节点时分页，页码与节点数明确显示；聚焦的节点始终保留在视图中。“导出当前视图 SVG”下载当前分页／聚焦范围，“导出完整图谱 SVG”下载所有节点和关系。四层完整性检查通过后可标记完成。完整性校验检查结构和引用，客观性、共指及情感解释仍需人工复核。

各层都有独立记录和复核状态。修改被引用证据后，依赖事实、事件和情感判断会标为“待复核”；删除证据或节点会清理关联，不静默保留悬挂引用。图谱编辑和导出仍在本地完成，不会自动上传研究素材或结果。

事实、事件和情感节点的内容或依据发生变化时，依赖它们的上层判断会要求复核。只修改本条复核状态不会使上层重新复核；未改动内容就点击保存，会保留四层完成状态、结果版本和关联边 ID。

事实、事件、情感编辑沿用证据页的“左侧编辑、右侧纵向列表”，左侧类别／主体与内容／依据横向分区。引用依据用可搜索的勾选卡片选择并显示已选数量，证据卡可直接回放。界面以淡色区分层级，以独立复核徽标表示确认状态。

证据窗修改会自动保存草稿。事实、事件和情感表单需点击对应保存按钮后写入图谱；切换阶段会保留未保存输入，保存其他表单不会清空它们。从证据再次“整理为事实”前，如果已有未保存的新事实，会先确认是否放弃该草稿。页面会标明尚未保存的表单，并在刷新或离开前提示。JSON 导出包含已保存的节点与关系，提交前请先保存各表单。

首页可下载“四层图谱示例”并通过“导入已有结果”打开，再关联演示任务包中的合成素材。示例包含完整的节点与箭头关系，但人物、事实与情感文字为结构占位，全部保留待复核状态，不可作为真实情感数据。

## 标注员操作

1. 从飞书下载自己分配的素材包并解压，打开管理员提供的标注网页。
2. 导入包内 `tasks.json`，核对批次 ID、任务 ID、标注员 ID。若没有清单，可以直接选择音视频，并手动填写三个 ID；正式双标应使用管理员清单以保证素材 ID 一致。
3. 选择对应的本地素材文件或文件夹。浏览器要求主动选择授权，不能通过填写 `D:\dataset\...` 这样的绝对路径读取任意文件。
4. 在播放器下方拖动时间轴创建时间窗，或填写起止秒数后点击“新建时间窗”。右侧时间窗列表纵向排列，底色、左侧色条和类别色块表示归属类别。
5. 选择时间窗后，证据类型与观察内容水平并排显示。记录主体线索、可观察内容及后续用途提示，必要时填写待整理的事实文字；点击“整理为事实”进入第二层。修改起止数字后离开输入框即可保存，拖动框身或边缘也可改时间。填写文本时不会触发标注快捷键。
6. 点击“证据标记完成并继续”整理下一条素材。证据就绪检查需要类型、主体线索和用途提示，观察／待整理文字至少填一项；未知主体线索可填 `unknown`。这与图谱页的“四层完成”分别检查，主体共指与各层解释在后续表单中确认。
7. 点击“导出本地结果”。Chrome／Edge 在 HTTPS 或 localhost 下可打开保存文件对话框；其他浏览器会使用下载。也可直接点击“下载 JSON”，以兼容内嵌浏览器或未授予原生保存权限的环境。导出可包含未完成草稿，状态在文件中明确记录，提交前应完成所有任务。
8. 将导出的 JSON 作为附件提交到飞书表单，无需重新上传音视频。

网页会把草稿保存到当前浏览器的 IndexedDB，不保存媒体文件。刷新或恢复草稿后，需要重新选择素材。清理缓存、无痕窗口、换设备或换网站地址会影响草稿可用性，因此应经常导出 JSON。可以导入导出的结果文件继续标注。

任务队列上方的“导入素材”可以选择 MP3、WAV、M4A 等音频或 MP4、WebM 等视频，也可混合多选，不需要先准备任务清单。导入会向当前清单补充新素材，已有项跳过，保留原任务 ID、人员信息、时间窗与标注。去重优先按相对路径；单独选择文件且没有路径时，用唯一文件名匹配，多路径同名则要求选择所属文件夹。已有素材尚未关联文件时会补充关联，但不会覆盖已关联文件。音频和视频用不同底色区分。

“删除选中任务素材”在确认后从当前清单移除该素材、时间窗和标注，保留本地原文件；删除最后一项会清除当前队列草稿并返回导入页面。导出入口位于任务队列下方。任务列表与时间窗列表各有独立滚动条，编辑标注时保留列表滚动位置。

同一份草稿建议只在一个标签页编辑。如果另一标签页已经更新草稿，旧标签页会拒绝覆盖并提示先导出本页结果，再恢复最新草稿。此时本页内存中的内容仍可导出。

成功打开网页后，应用会缓存自身的页面和脚本以便断网时重新打开；演示任务包不会自动缓存。网页更新时，请联网重新加载。恢复草稿功能依赖浏览器本地存储。

## 输入任务格式

任务清单文件不包含音视频字节，也不包含绝对磁盘路径：

```json
{
  "format": "trace-task-manifest",
  "schema_version": "1.0",
  "batch_id": "batch_001",
  "assignment_id": "batch_001_A",
  "annotator_id": "ann01",
  "items": [
    {
      "id": "source01_clip001",
      "title": "片段 001",
      "media_path": "media/clip001.mp4",
      "media_type": "video",
      "source_id": "source01",
      "clip_start_s": 600,
      "duration_s": 12,
      "video_fps": 25,
      "text": "按规范记录可观察证据。"
    }
  ]
}
```

音频使用 `media_type: "audio"` 和相应文件路径。`duration_s` 与 `video_fps` 可以省略；时长从本地文件读取。未提供帧率时按 0.1 秒步进；参考帧率不是对可变帧率文件逐帧准确性的保证。输出时间采用片段内的局部秒数，原片时间为 `clip_start_s + local_time`。

兼容原 Potato `data/items.json` 数组中的 `id`、`video_url`／`audio_url`、标题、说明与偏移元数据。这里 URL 字段只允许本地素材相对路径，不会发起远程媒体请求。

素材通过相对路径匹配；没有完整路径匹配时，可以使用唯一的文件名。出现同名歧义会拒绝关联。已有片段时，如果文件大小与结果记录不一致，会要求重新确认正确文件。文件名、大小和修改时间仅为追踪元数据，不是内容哈希或身份证明。

## 输出与飞书

导出文件命名为 `批次ID_任务ID_标注员ID_r版本号.json`，格式标识 `trace-annotations`，版本 `2.0`。每条素材包含 ID、来源、共同时间轴、偏移、文件元数据、完成状态、时间窗与观察字段；顶层 `graph` 保存各层节点与关联边。结果不嵌入素材字节，不上传到任何接口。

`graph` 包含 `entities`、`mentions`、`facts`、`events`、`emotion_states`、`emotion_transitions` 和 `links`。关系以 `links` 为准：证据支持事实、事实构成事件、事实支持情感判断、事件关联情感状态或变化。情感状态的先后关系由变化节点的起始／后续状态引用表示。

1.0 结果仍可导入：保留素材和时间窗 ID，将已有局部事实／观察文字迁为待复核的独立事实，并建立对应支持边。迁移不自动拆分复合句、不自动确认客观性或推断事件、情感。再次导出使用 2.0。旧版网页无法读取 2.0 图谱，请使用更新后的平台；首次迁移前建议保留原始 JSON 文件。

局部事实按时间窗保存在 `items[].segments[].annotations.local_fact`，与观察内容 `observation` 分别保存。旧结果没有 `local_fact` 时仍可导入。页面不再编辑不确定性、素材级局部事实草稿或操作备注；旧文件中已有的这些字段仍保留，避免导入再导出时丢失历史数据。

同一条双标任务必须保留相同素材 ID，使用不同任务 ID 和标注员 ID；两份结果分别保存，审核后再生成最终一组。标注员 ID 在离线工具中是用户填写的，不能作为飞书账号认证的替代。飞书提交表单应记录提交人，管理员按分配表核对身份与任务归属；首轮不向标注员开放其他人的结果。

建议飞书提交字段：批次 ID、任务 ID、标注员 ID、结果附件、提交时间、格式校验状态、审核状态。附件可批量收集后统一校验、双标比对、裁决和打包。当前版本不直接调用飞书 API，也不包含自动裁决或自动整理飞书附件的功能。

## GitHub Pages 发布

只把本目录中的程序、说明、测试与合成演示任务放入仓库，真实任务和结果放在仓库外。`private/`、`imports/`、`exports/` 和 `.env*` 已忽略，但不要依赖忽略规则代替人工核对。

在仓库 **Settings → Pages → Build and deployment** 选择 **Deploy from a branch**，分支 `main`，目录 `/ (root)`。等待部署结束后使用 GitHub 返回的 HTTPS 地址。`.nojekyll` 已包含；不需要后端服务器或构建步骤。是否能使用私有仓库发布 Pages 取决于 GitHub 套餐。

应用模块（包括 `graph.mjs`、`graph-ui.mjs`、`graph-view.mjs`）、样式和静态资源均使用相对路径，可运行在仓库子路径。页面源码可以公开；每位标注员的本地文件、草稿与结果不写入 GitHub 仓库。

## 本地维护与测试

本地调试版默认端口为 `http://127.0.0.1:8787/`，仅当前电脑可访问。双击 `启动浏览器标注.cmd` 会启动静态服务并打开浏览器；再次启动时会识别同端口的本项目并打开页面。关闭启动窗口或按 Ctrl+C 可停止该窗口启动的服务。保存源码后刷新页面即可查看修改，端口需要另设时运行 `python tools/preview.py --port 8788 --open`。本地浏览器草稿与 GitHub Pages 草稿分别保存，迁移时请导出并重新导入 JSON。

当前时间框流程：

1. 导入任务并选择本地素材，在播放器下方的时间轴按住拖动，松开后加入时间框列表；单击时间轴只定位播放。
2. 从右侧列表或时间轴选中一个时间窗，在播放器下方横向排列的类别与内容区填写标注。新窗为“待分类”，完成任务前必须分类。
3. “新建时间窗”始终用当前起止区间建立独立的空白时间窗，允许时间重叠；不复制已有类别或内容。“删除选中时间窗”在确认后删除当前窗口及其标注。
4. 在时间轴拖动框身可整体移动，拖动左右边缘可调整起止点。拖动时列表、起止输入和详情同步预览；视频画面随框身或左边缘预览起点，随右边缘预览终点。松开保存到浏览器草稿；按 Esc 或中断拖动会恢复原位置和拖动前画面。修改选中的起止数字后离开输入框即可保存，无需更新按钮。时间窗限制在素材范围内，重叠窗独立编辑。

右上角“设置”可选择导入入口、默认结果导出方式、画面高度与适配方式、默认播放速度、无参考帧率时的步进间隔。提供参考帧率的素材优先按 `1 / video_fps` 步进。设置保存在当前浏览器，不修改任务数据；实际帧解码精度由浏览器和素材编码决定。

管理员可双击 `启动浏览器标注.cmd`，或执行：

```powershell
python tools/preview.py
```

然后访问 `http://127.0.0.1:8787`。本地预览需要 Python；正式网页使用者无需安装它。不要通过双击 `index.html` 的 `file://` 地址运行 ES 模块应用。

核心格式、图谱关系与迁移测试：

```powershell
npm test
```

开发者执行浏览器验收时，先 `npm install` 并启动本地预览，再运行：

```powershell
npm run test:browser
npm run test:graph-browser
npm run test:frontend-browser
npm run test:relation-browser
```

测试依赖 Playwright，优先使用本机已有 Chromium，也可通过 `BROWSER_EXECUTABLE` 指定浏览器，或执行 `npx playwright install chromium` 安装测试浏览器。默认访问本地 8787 端口；设置 `BASE_URL` 可验收已发布网页。实际下载到磁盘的 JSON／SVG 会被校验；原生系统保存对话框的写入调用链使用模拟句柄验证。前端目标与验收对应关系见 [FRONTEND_ACCEPTANCE.md](FRONTEND_ACCEPTANCE.md)。

单次任务清单最多 5000 条，每条最多 1000 个片段，任务／结果 JSON 最大 20MB。较大批次请拆分。音视频编码支持由浏览器决定，建议先用目标浏览器验证真实素材。MP3 和 MP4 均已使用合成素材验证播放、时间窗标注与结果导出。

演示任务包 `samples/demo-task.zip` 仅包含合成测试视频和测试音，不含真人研究数据。
