# Bench Platform

当前版本：**v0.9**（应用版本 `0.9.0`）。更新内容见 [版本记录](./CHANGELOG.md)。

当前桌面界面使用 TRACE 视觉样式，设计参考、布局取舍和截图验证见 [桌面改版记录](./DESIGN_REFRESH.md)。

支持“多模态证据 → 客观事实 → 复合事件 → 主体情感脉络”的浏览器标注工作台。网页可发布到 GitHub Pages；素材、图谱和结果留在使用者的设备上。无需标注员安装 Python、Docker 或 Potato。

本项目是面向标注者的独立浏览器应用，包含时间窗、独立事实、事件、情感状态与变化，以及可回溯的有向关系图。各层由标注者填写，关联图按已保存的节点和关系自动生成。界面不提供待复核、复核状态或审核角色流程。

## 四层标注流程

任务列表每条素材都有“配对标注／更换标注”入口，显示已配对的 JSON 文件名。先选中具体素材，再选择它的标注文件；编号不符会拒绝配对，不改变其他素材。上方“导入已有结果”支持多选 JSON，按文件内素材 ID（允许去除媒体扩展名）或唯一素材文件名自动匹配现有队列；明确路径可消除同名文件歧义，编号与文件名相互矛盾时不导入。不会按当前选中项、共同时间轴或相近时间窗推断配对。

已有任务时，导入只替换匹配素材的标注，保留队列、其他素材的结果和已关联的本地视频。证据、事实、复合事件、情感状态、主体、引用选项和关联图谱均按当前素材隔离；切换素材不会复用上一条的内容。不同 JSON 中重复的 F001、S001 等节点 ID 会在队列内转换为不冲突的顺序 ID，并同步更新引用；原始 JSON 文件不变。配对信息保存在单素材 JSON 的 `items[0].annotation_source`。

新建标注使用按类型递增的顺序 ID：主体 `P001`、主体提及 `M001`、证据窗口 `W001`、事实 `F001`、复合事件 `E001`、情感状态 `S001`、关系 `R001`。列表和时间轴显示这些编号；计数随项目草稿及 JSON 保存，删除或撤回后不重用已分配编号。

1. **证据：** 导入 MP3／MP4 等素材，创建并分类时间窗。各页直接使用当前素材的时间，不再提供共同时间轴或时间轴来源选择。时间标识等元数据由系统维护，无需标注者填写。
2. **主体：** 在证据窗中输入名称，点击“新建并选中”；可以勾选多个主体。同一素材内已创建的主体可在后续窗口复用，取消勾选不会删除人物，刷新恢复后仍保留任务主体目录。同名主体可以分别建立并用独立 ID 区分，不自动合并。跨素材的统一主体映射从任务／结果文件保留，别名不用于猜测身份。
3. **事实：** 首次保存完整证据时生成默认事实，之后在事实页独立编辑描述、主体、时间和支持证据。一条事实可以引用多条证据，同一证据也可支持多个事实；事实操作不改写证据。人物陈述使用转述类事实，并填写发言者。
4. **复合事件：** 选择多条事实，精练成具体事件，参与主体沿用所选事实，并核对共同时间范围。情感状态也沿用事实／事件中的主体，情感变化连接同一主体的前后状态；不会从全局主体列表默认选择第一个人。一个事实可以支持多个事件。
5. **情感脉络：** 在左侧表单编辑状态，右侧情感状态区集中管理连边：勾选两个同主体状态，点击“连接选中状态”，直接在右侧增删连边。每条边可以标记视频中的事实／事件是否影响这次情感变化，选项为有影响、无影响、证据不足，默认未标注；修改自动保存。稳定情绪可以只有一个状态，不要求编造变化。
6. **关联图谱：** 在四条时间轨道上显示证据、事实、事件和情感，跨层连线随节点层级配色。默认全片显示，滚轮缩放时间尺度，拖动整个时间窗口平移显示区间。选中情感转移边时显示两端状态并编辑本次变化的证据、事实和事件依据。右侧节点按四类切换；证据列表依次显示编号、内容和小字整数秒起止时间。

各层都有独立的标注记录。删除证据或节点会清理关联，不静默保留悬挂引用。旧文件中的 `review_status` 只作为兼容元数据保留，不在标注界面展示，也不作为完成条件。图谱编辑和导出仍在本地完成，不会自动上传研究素材或结果。

事实、事件和情感节点的内容或依据发生变化时，相关时间与连接会同步更新；完成检查只核对引用、主体、时序等结构问题。未改动内容就点击保存，会保留完成状态、结果版本和关联边 ID。

事实、事件、情感编辑沿用证据页的“左侧编辑、右侧纵向列表”，左侧类别／主体与内容／依据横向分区。引用依据用可搜索的勾选卡片选择并显示已选数量，证据卡可直接回放。界面以淡色区分层级。

五个子页面为“证据／事实／复合事件／情感脉络／关联图谱”。证据内容及上层表单在输入停止约 650 毫秒后自动保存，无需点击保存按钮。事实和事件允许将未完成条目保存为草稿；尚未填写有效时间的情感表单先保存在浏览器草稿中，刷新恢复后继续填写。自动保存不移动输入光标；切换页面也会保存当前内容。

证据是原子记录，时间窗和描述只在证据页编辑。首次保存完整证据时生成一条默认事实，之后两者独立编辑；事实可关联多条证据，同一证据也可支持多个事实。修改事实内容或时间、删除事实不会反向改写证据内容或时间，也不会删除证据。删除默认事实后，证据再次自动保存不会将它重新生成。

证据主体表示该时间窗内涉及的人物。事实汇总可进一步限定这条事实实际描述的主体；回到证据页保存或完成素材时，会保留已经限定的范围，不把其他在场者自动加入事实。

每次启动或刷新均先显示导入页，不自动加载示例、素材队列或最近草稿。通过首页导入音视频或已有结果；已有浏览器草稿可点击“恢复草稿”后主动打开。左侧统一显示“任务列表”，保留“导入素材”和“导入已有结果”入口。开发测试使用的 `samples/` 合成示例保留在仓库内，不在启动页预加载或展示为默认任务。

## 事件时间：事实时间窗并集

复合事件发生时间取构成事实发生时间窗的并集；事实未单独调整时间时，默认使用支持证据的呈现时间窗。先使用素材的共同时间轴及 `time_offset_s`（未设置时使用 `clip_start_s`）对齐，再合并重叠或首尾相接的窗口，保留实际空档。例如 `[10,20]`、`[15,25]`、`[100,110]` 得到 `[10,25] ∪ [100,110]`。事件时间条只读，可点击选择或回看，不单独拖动或缩放；应调整对应事实，而不改写证据。

事件编辑区和事件列表显示分段时间。JSON 导出的 `derived.event_time_ranges` 按事件 ID 存储 `{status, timeline_id, time_ranges}`，其中每段为 `{start_time, end_time}`，单位为共同时间轴上的秒。事件时间正常时为 `derived`，无法确定时为 `unresolved`；重新导入后，再导出会根据构成事实重新计算，不采用独立事件时间覆盖。

证据的 `items[].segments[].start_time/end_time` 表示素材内的呈现位置，事实可单独指定发生时间，保存为 `timeline_id/time_ranges`，解释保存为 `time_note`。各层时间含义不同，但保存的关联必须满足：每条上游标注的结束时间不晚于下游结束时间。上游可更早开始，也可与下游重叠，不要求完全包含。多段时间窗使用最晚结束时间比较；跨素材先按时间偏移对齐。同一事实的每条证据分别检查，不能用一条较早证据代替检查其他证据。恢复默认时间不会改写证据。

导出的 `time_semantics` 声明各层时间含义及秒单位；`derived.fact_temporal` 按事实 ID 分别提供 `occurrence`、`evidence_presentation` 和不相交的 `disjoint_evidence_ids`。时间先后约束不依赖因果关系类型：证据→事实、事实→复合事件、事实／复合事件→情感状态均检查。情感变化边的内容依据以目标情感状态的结束时间为上界。复合事件仍取构成事实的并集；事实调整引起事件变晚时，会继续校验它关联的情感状态。

建边、修改引用、填写时间、拖动和缩放时间窗都会校验。失败时保留上次有效标注，冲突输入保留为待调整草稿并持续显示警告；保存或导出前仍有冲突时必须先调整。不会自动移动、延长其他节点，也不接受仅填写解释来绕过约束。默认时间相同允许通过，浮点误差容差为 0.000001 秒。缺少时间的未完成草稿仍按原有完整性规则处理。

构成事实没有完整关联支持证据或混用了不同时间轴时，草稿仍可导出，派生项标为 `status: "unresolved"`，附 `reason`，不输出可能误导的完整事件时间。修改时间窗、时间偏移或构成关系后，下次显示及导出会重新计算。

## 各层时间轴与回看

时间轴条目统一显示“编号_主体”，下一行显示内容描述。关联图固定为证据、事实、复合事件、情感四条轨道，同层重叠节点在层内小幅上下错位。默认全片显示；滚轮向上放大、向下缩小时间尺度，以鼠标位置为缩放锚点，并限制在全片边界内。全片概览条上的矩形窗口表示当前显示区间；拖动整个窗口实时平移图谱，并保持覆盖时长不变；在概览条上滚动滚轮可调整窗口覆盖时长，框宽同步变化；也可填写“时间跨度 / 秒”。选中节点不改变当前范围。图下方显示上游概要；右侧节点列表通过四类切换，每类单独搜索和滚动。观察事实为绿色，转述事实为蓝色，图谱、时间轴和列表保持一致；跨层线从起点颜色渐变到终点颜色，情感转移线沿用情感层颜色。

完整节点列表保留矩形卡片：证据显示编号与时间窗、内容及类型角标，类别用颜色区分；事实显示编号、内容、参与主体及事实类型角标；事件显示编号、内容和参与主体；情感状态显示主体和状态。关联图不再单独显示“情感状态的上下游关系”版块。

情感脉络使用当前素材的时间，按规范主体 ID（`subject_id`）分行；同一主体的所有状态共用一行，时间重叠也不拆行，同名但 ID 不同的主体仍分开。情感变化只在实际状态框之间绘制方向箭头，不额外生成“前／后”标注或占用轨道。重复记录同一对状态的连接只画一条线，原始关系仍完整保留。

情感状态至少需要一条事实或一个复合事件支撑，二者无需同时选择。新勾选事件时，编辑器默认勾选其构成事实，之后可以手动取消部分乃至全部事实；切换页面、保存和重新打开均保留实际选择，不会自动补回。取消事件不会清除已经选择的独立事实。仅事件支撑时，完整性检查通过事件构成事实追溯证据，不自动生成 `fact → emotion_state` 边；有直接事实时，以明确选择的事实子集检查其证据范围。

情感状态连边使用独立多选：在右侧列表或时间轴勾选两个状态，再点击右侧“连接选中状态”。多选不改变单条编辑对象，重复连接不生成重复边，删除连边不删除状态。新边导出为 `emotion_state → emotion_state`、`type: "transitions_to"`；可选字段 `content_influence` 为 `yes`、`no`、`insufficient_evidence`，缺省表示未标注。该字段表示视频事实／事件对这次情感变化的影响，不表示一个情感状态对另一个状态的因果影响。状态的逐事件因果依据仍存放在事件至状态边的 `note`。

选中右侧状态连边或图谱中的情感转移边，可以多选对应证据、事实和复合事件，并逐条填写关系与判断依据。边的 `content_refs` 保存 `{node_type, node_id, relation, note}`，`relation` 可为 `associated_with`（有关联）、`influences`（影响本次变化）、`unrelated`（无关联／无影响）或 `insufficient_evidence`（证据不足）；边的 `note` 保存综合说明。增删这些对应关系不会改动原节点或两个状态各自的依据；可另点“查看／编辑原节点”。各项自动保存，可撤回，单素材导出保留本素材依据，外部依据另存于 `cross_material_references`。

旧版 `emotion_transitions` 节点及其事件关系原样导入、导出，不自动转换为状态因果；可在相关状态内展开历史记录查看。点击历史变化的时间条会定位到对应状态，不再打开独立变化编辑区。可运行 `npm run test:emotion-browser` 验证整合流程，`test:relation-browser` 为同一关系编辑测试的兼容入口。

工作台顶部“撤回”按钮及 Ctrl／Cmd＋Z 支持撤回已保存的标注修改，包括证据、事实、事件、情感时间框，以及新建／删除和连边。一次联动操作会整体恢复底层证据、关系及兼容元数据，结果版本仍递增以保证草稿保存一致。输入框内的快捷键保留原生文字撤销；拖动过程中使用 Esc 或 Ctrl／Cmd＋Z 只取消预览。撤回历史在当前页面会话内保留多步，刷新或导入任务会重新开始，不写入导出文件。可运行 `npm run test:undo-browser` 验证多选与撤回。

证据、事实、复合事件和情感时间轴均将不重叠标注排入同一行，仅在时间窗重叠时增加轨道；点击标注框直接选中对应内容，仍可拖动或调整边界。情感时间轴保留状态勾选与 Ctrl／Cmd 多选。

事实时间初始取支持证据的时间窗并集，拖动后保存独立发生时间，不改变证据；与证据不相交时在事实页填写时间说明。事件发生时间始终取构成事实窗并集，不提供独立时间覆盖。即使多个事实时间重叠，事实记录、内容、ID 和关联仍分别保留。事件的时间导出在 `derived.event_time_ranges`。

情感状态框可移动、缩放边界，也可填写起止时间。修改状态时间后，连接箭头会自动跟随；箭头表示转移方向，中间空档不作为状态持续时间。选中转移边时，两端的实际状态标注仍可查看，方向用箭头表示，不显示“变化前／变化后”标题。

各层均可划选或填写起止时间创建草稿。事实层只新建带独立时间的事实草稿，事件层新建事件及构成事实草稿，均不会隐式创建证据；随后可选择已有证据。情感层新建状态草稿。拖动期间仅预览，松开保存时间，Esc 或指针取消会还原。

点击时间条选择对应标注并定位当前素材，点击刻度可定位播放，刻度也支持左右方向键、Home 和 End。当前素材不覆盖某个共同时间位置时会提示，可通过标注中的支持证据回看对应素材。播放时红线显示当前素材在共同时间轴上的位置。

时间轴提供搜索、放大、缩小、全览和横向滚动；每页最多显示 80 条，超出后翻页。未关联证据或时间轴冲突的条目显示在“时间待补充”中，仍可点击编辑。查看、缩放和定位不修改标注数据。可运行 `npm run test:timeline-browser` 验证拖动、缩放、取消、划选及导出联动。

## 标注员操作

1. 从飞书下载自己分配的素材包并解压，打开管理员提供的标注网页。
2. 导入包内 `tasks.json`，核对批次 ID、任务 ID、标注员 ID。若没有清单，可以直接选择音视频，并手动填写三个 ID；正式双标应使用管理员清单以保证素材 ID 一致。
3. 选择对应的本地素材文件或文件夹。浏览器要求主动选择授权，不能通过填写 `D:\dataset\...` 这样的绝对路径读取任意文件。
4. 在播放器下方拖动时间轴创建时间窗，或填写起止秒数后点击“新建时间窗”。右侧时间窗列表纵向排列，底色、左侧色条和类别色块表示归属类别。
5. 选择时间窗后，添加或勾选主体并填写证据内容；输入停止后自动保存。未选择时间窗时不显示编辑头部和空白提示。修改起止数字后离开输入框即可保存，拖动框身或边缘也可改时间。填写文本时保留正常的文字快捷键。
6. 点击“证据标记完成并继续”保存本素材的事实并整理下一条。证据就绪检查需要证据类型、主体、事实描述和用途提示；未知人物也应作为独立主体建立，只有人工确认相同身份后才复用。完成素材不会自动确认事实、事件或情感解释；图谱页只用于查看和编辑关联，不承担独立验收。
7. 点击“保存当前素材 JSON”或“下载当前 JSON”，保存当前视频／音频对应的独立文件。点击“批量导出独立 JSON”可选择文件夹，将每条素材分别写入文件；不支持文件夹保存时会下载 ZIP，解压后仍是每条素材一个 JSON。导出可包含未完成草稿。
8. 将导出的 JSON 作为附件提交到飞书表单，无需重新上传音视频。

网页会把草稿保存到当前浏览器的 IndexedDB，不保存媒体文件。刷新后先回到导入页，通过“恢复草稿”选择继续，再重新关联本地素材。切换素材时，各自的新建事实、事件和情感表单草稿分别保留。清理缓存、无痕窗口、换设备或换网站地址会影响草稿可用性，因此应经常导出 JSON。可以导入导出的结果文件继续标注。

任务队列上方的“导入素材”可以选择 MP3、WAV、M4A 等音频或 MP4、WebM 等视频，也可混合多选，不需要先准备任务清单。导入会向当前清单补充新素材，已有项跳过，保留原任务 ID、人员信息、时间窗与标注。去重优先按相对路径；单独选择文件且没有路径时，用唯一文件名匹配，多路径同名则要求选择所属文件夹。已有素材尚未关联文件时会补充关联，但不会覆盖已关联文件。音频和视频用不同底色区分。

“删除选中任务素材”在确认后从当前清单移除该素材、时间窗和标注，保留本地原文件；删除最后一项会清除当前队列草稿并返回导入页面。导出入口位于任务队列下方。任务列表与时间窗列表各有独立滚动条，编辑标注时保留列表滚动位置。

同一份草稿建议只在一个标签页编辑。如果另一标签页已经更新草稿，旧标签页会拒绝覆盖并提示先导出本页结果，再恢复最新草稿。此时本页内存中的内容仍可导出。

成功打开网页后，应用会缓存自身的页面和脚本以便断网时重新打开；演示任务包不会自动缓存。网页更新时，请联网重新加载。恢复草稿功能依赖浏览器本地存储。

## 输入任务格式

任务清单文件不包含音视频字节，也不包含绝对磁盘路径：

```json
{
  "format": "trace-task-manifest",
  "schema_version": "1.0",
  "batch_id": "batch_001",
  "assignment_id": "batch_001_A",
  "annotator_id": "ann01",
  "items": [
    {
      "id": "source01_clip001",
      "title": "片段 001",
      "media_path": "media/clip001.mp4",
      "media_type": "video",
      "source_id": "source01",
      "clip_start_s": 600,
      "duration_s": 12,
      "video_fps": 25,
      "text": "按规范记录可观察证据。"
    }
  ]
}
```

音频使用 `media_type: "audio"` 和相应文件路径。`duration_s` 与 `video_fps` 可以省略；时长从本地文件读取。未提供帧率时按 0.1 秒步进；参考帧率不是对可变帧率文件逐帧准确性的保证。输出时间采用片段内的局部秒数，原片时间为 `clip_start_s + local_time`。

兼容原 Potato `data/items.json` 数组中的 `id`、`video_url`／`audio_url`、标题、说明与偏移元数据。这里 URL 字段只允许本地素材相对路径，不会发起远程媒体请求。

素材通过相对路径匹配；没有完整路径匹配时，可以使用唯一的文件名。出现同名歧义会拒绝关联。已有片段时，如果文件大小与结果记录不一致，会要求重新确认正确文件。文件名、大小和修改时间仅为追踪元数据，不是内容哈希或身份证明。

## 输出与飞书

每条素材单独导出一个 JSON，默认使用素材文件名，例如 `zh001.json`。批量导出时同名素材自动追加素材 ID 与序号，避免覆盖。格式标识为 `trace-annotations`，版本 `2.0`，`items` 只含当前一条素材，顶层 `graph` 保存该素材的事实、事件、情感及关系；`source_item_id` 标明所属素材。跨素材关联保存在 `cross_material_references` 中，不制造悬挂的本地图谱引用。新建事实、事件和状态记录 `item_id`，暂时移除证据连接的草稿仍会保留在对应文件中。结果不嵌入音视频字节，不上传到任何接口。

`graph` 包含主体、提及、事实、事件、情感状态和关系。关系以 `links` 为准：证据支持事实、事实构成事件、事实支持情感判断、事件关联或导致情感状态；情感变化由两个状态之间的 `transitions_to` 有向边表示。

1.0 结果仍可导入：保留素材和时间窗 ID，将已有局部事实／观察文字迁为待复核的独立事实，并建立对应支持边。迁移不自动拆分复合句、不自动确认客观性或推断事件、情感。再次导出使用 2.0。旧版网页无法读取 2.0 图谱，请使用更新后的平台；首次迁移前建议保留原始 JSON 文件。

统一录入的事实描述保存在 `items[].segments[].annotations.observation`，保存后与对应 `graph.facts[].text` 同步。可选 `annotations.subject_ids` 记录该证据的多个统一主体 ID，`annotations.fact_id` 记录当前页面编辑的主事实；支持关系仍以 `graph.links` 为准。可选 `items[].subject_ids` 保存本素材可复用的主体目录。导入会校验这些引用，旧文件未含新字段时仍按原主体线索读取。

旧版 `local_fact` 与 `observation` 不同的内容分别保留，`local_fact` 在折叠区只读查看。页面不再编辑不确定性、素材级局部事实草稿或操作备注；旧文件中已有的这些字段仍保留，避免导入再导出时丢失历史数据。

同一条双标任务必须保留相同素材 ID，使用不同任务 ID 和标注员 ID；两份结果分别保存，审核后再生成最终一组。标注员 ID 在离线工具中是用户填写的，不能作为飞书账号认证的替代。飞书提交表单应记录提交人，管理员按分配表核对身份与任务归属；首轮不向标注员开放其他人的结果。

建议飞书提交字段：批次 ID、任务 ID、标注员 ID、结果附件、提交时间、格式校验状态、审核状态。附件可批量收集后统一校验、双标比对、裁决和打包。当前版本不直接调用飞书 API，也不包含自动裁决或自动整理飞书附件的功能。

## GitHub Pages 发布

只把本目录中的程序、说明、测试与合成演示任务放入仓库，真实任务和结果放在仓库外。`private/`、`imports/`、`exports/` 和 `.env*` 已忽略，但不要依赖忽略规则代替人工核对。

在仓库 **Settings → Pages → Build and deployment** 选择 **Deploy from a branch**，分支 `main`，目录 `/ (root)`。等待部署结束后使用 GitHub 返回的 HTTPS 地址。`.nojekyll` 已包含；不需要后端服务器或构建步骤。是否能使用私有仓库发布 Pages 取决于 GitHub 套餐。

应用模块（包括 `graph.mjs`、`graph-ui.mjs`、`graph-view.mjs`）、样式和静态资源均使用相对路径，可运行在仓库子路径。页面源码可以公开；每位标注员的本地文件、草稿与结果不写入 GitHub 仓库。

## 本地维护与测试

本地调试版默认端口为 `http://127.0.0.1:8787/`，仅当前电脑可访问。双击 `启动浏览器标注.cmd` 会启动静态服务并打开浏览器；再次启动时会识别同端口的本项目并打开页面。关闭启动窗口或按 Ctrl+C 可停止该窗口启动的服务。保存源码后刷新页面即可查看修改，端口需要另设时运行 `python tools/preview.py --port 8788 --open`。本地浏览器草稿与 GitHub Pages 草稿分别保存，迁移时请导出并重新导入 JSON。

当前时间框流程：

1. 导入任务并选择本地素材，在播放器下方的时间轴按住拖动，松开后加入时间框列表；单击时间轴只定位播放。
2. 从右侧列表或时间轴选中一个时间窗，在播放器下方横向排列的类别与内容区填写标注。新窗为“待分类”，完成任务前必须分类。
3. “新建时间窗”始终用当前起止区间建立独立的空白时间窗，允许时间重叠；不复制已有类别或内容。“删除选中时间窗”在确认后删除当前窗口及其标注。
4. 在时间轴拖动框身可整体移动，拖动左右边缘可调整起止点。拖动时列表、起止输入和详情同步预览；视频画面随框身或左边缘预览起点，随右边缘预览终点。松开保存到浏览器草稿；按 Esc 或中断拖动会恢复原位置和拖动前画面。修改选中的起止数字后离开输入框即可保存，无需更新按钮。时间窗限制在素材范围内，重叠窗独立编辑。

右上角“设置”可选择导入入口、默认结果导出方式、画面高度与适配方式、默认播放速度、无参考帧率时的步进间隔。提供参考帧率的素材优先按 `1 / video_fps` 步进。设置保存在当前浏览器，不修改任务数据；实际帧解码精度由浏览器和素材编码决定。

管理员可双击 `启动浏览器标注.cmd`，或执行：

```powershell
python tools/preview.py
```

然后访问 `http://127.0.0.1:8787`。本地预览需要 Python；正式网页使用者无需安装它。不要通过双击 `index.html` 的 `file://` 地址运行 ES 模块应用。

核心格式、图谱关系与迁移测试：

```powershell
npm test
```

测试依赖 Playwright，优先使用本机已有 Chromium，也可通过 `BROWSER_EXECUTABLE` 指定浏览器，或执行 `npx playwright install chromium` 安装测试浏览器。默认访问本地 8787 端口；设置 `BASE_URL` 可验收已发布网页。实际下载到磁盘的 JSON／SVG 会被校验；原生系统保存对话框的写入调用链使用模拟句柄验证。前端目标与验收对应关系见 [FRONTEND_ACCEPTANCE.md](FRONTEND_ACCEPTANCE.md)。

单次任务清单最多 5000 条，每条最多 1000 个片段，任务／结果 JSON 最大 20MB。较大批次请拆分。音视频编码支持由浏览器决定，建议先用目标浏览器验证真实素材。MP3 和 MP4 均已使用合成素材验证播放、时间窗标注与结果导出。

事实、复合事件和情感状态均允许输入新主体名字后按回车添加，不需要该主体先在证据中出现，也不自动为证据补主体提及。主体名字输入框为空时按退格取消最后一个主体选择，不删除全局主体。

非文字输入状态下，Backspace / Delete 删除当前选中的节点或情感变化边，Ctrl+Z 或撤回按钮可恢复。跨层映射线始终显示，选中情感节点仍突出关联的复合事件、事实、证据及跨层连线；不沿情感变化边传播到另一个状态。只有情感变化边支持额外选中，选中后只突出直接连接的情感状态，不向证据、事实或事件扩展，也不改变跨层映射线的显示。

当前流程可运行 `npm run test:workflow-browser` 验证自动保存、独立事实时间、多证据引用、新主体、快捷删除与选边规则。

选中事实、事件或情感节点后，可再选其中一个直接上级关联。图谱中点击直接上级节点或图下方的直接上级条目，编辑页点击已勾选的支持卡片内容均可选中关联。此时退格仅解除该关联，不删除任何一端节点，且可撤回。重新选中主节点后退格才会删除主节点；图谱节点双击可直接切换为查看该节点。
